# API Contract

> **Rule #1:** this file is the agreement between frontend, backend and database. Change it **first**, in a small PR or a team-chat message everyone acknowledges, and **then** change code.

- **Base URL (dev):** `http://localhost:4000/api`. The frontend calls `/api/...`, and Vite proxies it.
- **Format:** JSON in, JSON out. Header: `Content-Type: application/json`.
- **Casing:** JSON keys are **camelCase**. Database columns are snake_case, and the server converts between them.
- **IDs:** UUID strings.
- **Timestamps:** ISO-8601 UTC strings, for example `"2026-11-22T10:47:25.561Z"`.
- **Postman:** import [`postman_collection.json`](./postman_collection.json). It sets the `baseUrl` variable for you.

## Response envelope

Every endpoint returns one of these two shapes:

```jsonc
// ✅ Success
{
  "success": true,
  "data": { },                 // object, array or null
  "meta": { }                  // optional — pagination etc.
}

// ❌ Error
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR", // machine-readable, stable
    "message": "Validation failed", // human-readable
    "details": { "title": "Title must be at least 3 characters" } // optional, field → message
  }
}
```

The frontend `apiClient` unwraps this envelope. It resolves with `{ data, meta }` or throws an `ApiError { status, code, message, details }`. `useForm` automatically shows `details` under the matching form fields.

### Status codes and error codes

| HTTP | `error.code` | When |
| --- | --- | --- |
| 200 | — | OK (GET, PATCH, DELETE) |
| 201 | — | Created (POST) |
| 400 | `BAD_REQUEST` | Malformed JSON, or a constraint violated in the DB |
| 401 | `UNAUTHORIZED` | Not logged in (reserved for when auth is added) |
| 403 | `FORBIDDEN` | Logged in but not allowed |
| 404 | `NOT_FOUND` | Unknown route, or a record that doesn't exist |
| 409 | `CONFLICT` | Unique constraint violated |
| 413 | `PAYLOAD_TOO_LARGE` | Body over 1 MB |
| 422 | `VALIDATION_ERROR` | Request failed Zod validation (`details` lists the fields) |
| 500 | `INTERNAL_ERROR` | Bug or database failure (development responses include `debug`) |

### Pagination `meta`

```json
{ "page": 1, "pageSize": 10, "total": 42, "totalPages": 5 }
```

## Health

### `GET /api/health`
Liveness check. It does not touch the database.

```json
{ "success": true, "data": { "status": "ok", "environment": "development", "database": "memory", "uptime": 12, "timestamp": "…" } }
```

`database` is `"supabase"` when `SUPABASE_*` is configured and `"memory"` otherwise.

### `GET /api/health/db`
Readiness check. It runs a cheap query against the active data source.

```json
{ "success": true, "data": { "status": "ok", "database": "supabase", "latencyMs": 38 } }
```

## Items (example resource)

### Item object

| Field | Type | Notes |
| --- | --- | --- |
| `id` | uuid | Generated by the server or DB |
| `title` | string | 3–120 chars, **required** |
| `description` | string | ≤ 1000 chars, default `""` |
| `status` | enum | `todo` \| `in_progress` \| `done` \| `archived`, default `todo` |
| `priority` | enum | `low` \| `medium` \| `high`, default `medium` |
| `category` | string | 1–60 chars, **required** |
| `createdAt` | ISO string | Read-only |
| `updatedAt` | ISO string | Read-only, set automatically |

### `GET /api/items`
List items with pagination, search, filter and sort.

| Query | Type | Default | Notes |
| --- | --- | --- | --- |
| `page` | int ≥ 1 | `1` | |
| `pageSize` | int 1–100 | `10` | |
| `search` | string | — | Case-insensitive match on title or description |
| `status` | enum | — | One of the statuses |
| `sort` | `createdAt` \| `updatedAt` \| `title` \| `status` \| `priority` | `createdAt` | |
| `order` | `asc` \| `desc` | `desc` | |

```http
GET /api/items?page=1&pageSize=2&status=todo
```
```json
{
  "success": true,
  "data": [
    { "id": "6f1c2b1e-0000-4000-8000-000000000006", "title": "Seed demo data", "description": "…", "status": "todo", "priority": "medium", "category": "Database", "createdAt": "…", "updatedAt": "…" }
  ],
  "meta": { "page": 1, "pageSize": 2, "total": 4, "totalPages": 2 }
}
```

### `GET /api/items/:id`
Returns `200 { data: Item }`. If the id doesn't exist, returns `404 NOT_FOUND`. If the id isn't a UUID, returns `422 VALIDATION_ERROR`.

### `POST /api/items`
```json
{ "title": "Build onboarding flow", "category": "Frontend", "priority": "high" }
```
Returns `201 { data: Item }`. Fields you leave out get their defaults.

Validation failure example (`422`):
```json
{ "success": false, "error": { "code": "VALIDATION_ERROR", "message": "Validation failed",
  "details": { "title": "Title must be at least 3 characters", "category": "Category is required" } } }
```

### `PATCH /api/items/:id`
Partial update. Send **only** the fields you want to change; the others keep their current values. An empty body returns `422`.
```json
{ "status": "done" }
```
Returns `200 { data: Item }`.

### `DELETE /api/items/:id`
Returns `200 { data: null }`, or `404` if the item doesn't exist.

## Adding an endpoint (checklist)

1. Add a row above, with the request and response shapes.
2. **DB:** create or alter the table in `database/schema.sql` and add seed rows.
3. **Backend:** add a validator, a service, a controller and a route, then register it in `routes/index.js`. Add a test to `server/tests/api.test.js`.
4. **Frontend:** add a service in `client/src/services/` with `mock` and `http` branches that return the same shape.
5. Add the request to the Postman collection.
6. Flip the status to 🟢.
